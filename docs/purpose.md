# fuwa の目的

fuwa は、AI に曲を作らせることを前提に設計された DAW。人間は MIDI を編集しない。

## 背景

AI を使った音楽制作は、大きく3つのアプローチに分かれる。

1. **人間がメインで作り、一部を AI で楽にする** — 既存の制作フローはそのままに、補助として AI が入る
2. **AI にオーディオを生成させる** — プロンプトから完成した音声が出てくる。制作物への介入余地がほとんどない
3. **AI 前提で作られた DAW** — 制作環境そのものを AI 向けに設計する

fuwa は3番目を取る。

ただし既存の「AI 前提」を謳うソリューションも、実態は人間向けに最適化された UI の延長に AI を付け足したものが多い。fuwa はここをもっと振り切る。

## なぜ既存の DAW を AI に操作させないのか

Computer Use で既存の DAW を操作させるアプローチもありうる。これを採らないのは、既存 DAW の UI が人間向けに最適化されているためトークン効率が悪いから。画面を読み、マウスを動かし、GUI の状態を推測する分のコストがすべて無駄になる。計測したわけではないが、構造的にそうなるはず。

もし既存 DAW を操作した方が効率が良いという結果になったとしたら、それは fuwa の出来が悪いか、LLM が既存 DAW の知識を大量に持っていることによるものだと考える。いずれにせよ Computer Use が最適解であるはずはないので、そこは理想の未来に賭ける。

fuwa が既存 DAW より優れているとすれば、その理由は AI が直接叩ける API を持っていることになる。したがって API 設計は実装詳細ではなく、プロダクトの核心として扱う。

ただしここで言うトークン効率は Computer Use との比較の話であって、絶対的な最小化を目的にするわけではない。少ないに越したことはない、という程度に捉える。

## 人間は編集しない

Vibe Coding と同じく、最初から AI に作らせ、人間はコードを——ここでは MIDI を——編集しない。

この前提を置くと、UI は「AI に作らせて、聴いて、また頼む」というフローに最適化される。編集機能を持たないぶん、ユーザーとしても開発者としても極端にシンプルになる。

現実には AI に任せきれない領域が残るため、当面は人間が担う部分がある。

- **MIDI** — 触らない。ここは AI に任せる
- **VST インストゥルメントの選択** — 当面は人間。AI にどこまで任せられるか未知数なので、人間用の UI は残す
- **ミキシング** — 当面は人間。AI の能力が最も読めない領域

この境界は暫定的なもの。実際にどこまで任せられるかは作って確かめるしかないので、仮説を立てて検証しながら動かしていく。

## 人間の操作

編集をしないため、人間の操作は次に収束する。

- プロンプトを打つ
- 聴く
- ミキサーを触る
- トラックの音源を選ぶ
- 保存する / オーディオを書き出す

したがって画面の主役はトラック一覧、トランスポート、ミキサー、そしてセッションパネルになる。

やり直しは版管理をせず、常に上書きとする。気に入らなければ AI に「さっきのに戻して」と頼めばよい。コーディングでの経験上それで大体戻るので、不都合が生じてから考える。

### セッションパネルを内蔵する

エージェントとの会話は fuwa の中に置く。外部のターミナルでエージェントを起動する形にすると、生成のたびに画面を行き来することになって体験が途切れる。また画面で選んだ範囲をプロンプトに渡すような操作は、入力欄が自前でなければ成立しない。

会話は読む。生成の指示だけでなく「こういう曲調で参考になる曲はあるか」といった相談もするため、エージェントの返答を読む領域が要る。ただしコーディングに比べれば、読む量も過去に遡る頻度も少ない。

自前のチャット UI は作らず、claude や codex の TUI をそのまま端末として埋める。独自の UI に置き換えると、スラッシュコマンドも承認フローもモード切替も作り直しになり、本家が変わるたびに追随し続けることになる。端末をそのまま出せば、作る量も維持費も小さく済む。

パネルは左に置く。会話は縦に伸びるし、細かい指示を書くときは入力も複数行になるので、下部のバーには収まらない。ただし横幅を取るため畳めるようにし、聴いて整えるときは画面を広く使えるようにする。

内蔵の入力欄は API のいちクライアントに過ぎず、特権的な経路を持たない。エージェント CLI 側の変更で内蔵の実行部分が壊れても、外部から API を叩けば fuwa は動く。

## 想定ユーザー

作者一人。

当面のユースケースは、現状の AI 技術で作れる範囲の曲を作って X などに投稿すること。ゆくゆくは商用のゲーム BGM などに活用したいが、先は長いのでのんびり進める。

商用の音楽制作を完結させるには AI の作曲能力はまだ心許ないが、それは時間が解決すると考えている。

## 公開方針

コードは公開するが、OSS として Issue / PR を外部に開くことはしない。運用の手間を避けるため。
