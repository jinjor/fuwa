# アーキテクチャ

開発環境と道具立ては [development.md](development.md) を参照。

## 置き場所

```
src/
  model/     プロジェクトの状態と、それに関する規則。トラック、ノート、ミックス、テンポ。
  plugin/    プラグインのホスティング。VST3 をここに閉じ込める。
  audio/     オーディオデバイスの入出力。リアルタイムスレッドを所有する。
  engine/    再生。トランスポートを進め、モデルの音をプラグインに通して出力に流す。
  api/       外部からの操作を受ける IPC サーバ。
  app/       組み立てと main()。
test/        各層のテスト。src/ と同じ名前のディレクトリに置く。
vendor/      外部から持ってきたもの。VST3 SDK など。
```

迷ったときは「その知識は誰のものか」で決める。ノートの長さを知っているのは model、`IAudioProcessor` の呼び方を知っているのは plugin、バッファのサンプル数を知っているのは audio。

## 依存の向き

```
app → api → engine → plugin
                   → model
                   → audio
```

上から下へのみ依存する。逆流させない。

`plugin` `model` `audio` は互いを知らない。この 3 つの独立が構造の要で、崩すと曲データが
プラグインの都合に汚れ、リアルタイムスレッドからデータ構造を触ることになり、プラグインを
オフラインでレンダリングできなくなる。

## 各層の責務

### model

プロジェクトの状態そのものと、それを扱う規則。ノート、トラック、テンポ、ミックスの値と、
それらに対する問いへの答えがここにある。

- 状態と、それに関する規則だけ。ファイル I/O もリアルタイム処理も知らない
- **テンポと拍子は単一の値ではなく、位置つきの列**（MIDI の Set Tempo / Time Signature と同じ）。拍 → 秒の変換は区間ごとの積分になる。小節 ↔ 拍の変換には拍子が要るので、小節番号でアドレスする以上ここは避けて通れない
- 範囲への操作の意味論を決めるのはこの層。「17〜20 小節を置き換える」と言われたとき、境界をまたぐノートを切るのか、残すのか、消すのか
- 不変条件（pitch や velocity の範囲、長さ、重なりの可否）を守るのもこの層
- トラックは**安定した id** で識別する。表示名は別の属性（表示名をアドレスにすると、改名した瞬間に指せなくなる）
- 範囲（トラック + 小節の区間）を名指しできる型を持つ。API から「17〜20 小節の drums」を指すため、および UI で選択した範囲をプロンプトに渡すため
- 制御スレッドからのみ触る。リアルタイムスレッドには渡さない

### plugin

プラグインを読み込み、鳴らす。

- **VST3 の型を上位層に漏らさない。** `pluginterfaces/` の include はこの層の中だけ
- 将来 AU を足すならこの層に実装を増やす。ただし使う予定のない AU のために抽象を厚くはしない
- プラグインの GUI（エディタ）もこの層が持つ。NSView が出てくるので ObjC++ になる

### audio

CoreAudio との境界。デバイスを開き、リアルタイムコールバックを回す。

- **リアルタイムスレッドを所有する唯一の層**
- オフラインレンダリングも同じ入り口を通す。デバイスに出すかバッファに書くかの違いだけにする。耳を使わずに音を確かめられるのはこれによる
- 上位層のデータ構造を直接触らない

### engine

再生位置を進め、モデルの音をプラグインに通し、出力に流す。

- 制御スレッドとリアルタイムスレッドの橋渡しをする。モデルの変更はロックフリーの受け渡しでリアルタイム側に届ける。リアルタイム側からモデルを読みに行かない
- トランスポート（再生、停止、シーク）を持つ

### api

外部のエージェントと内蔵の UI から操作を受ける。

- モデルを変更し、エンジンに指示を出す。音そのものには触らない
- **内蔵 UI に特権的な経路を持たせない。** UI もエージェントも同じ API を通る。UI にしかできない操作が生まれると、API がプロダクトの本体であるという前提が崩れる
- **コマンドを解釈するのは `api/command` の 1 箇所だけ。** CLI は argv をそのまま運ぶ。両側に解釈が散ると、CLI 経由と UI 経由で意味が食い違う
- 線の上の形式は `api/protocol.h` に書いてある。argv を入れた JSON の配列を 1 行送り、`{"code":…,"text":…}` が 1 行返る

### app

組み立てだけ。各層の生成と寿命の管理、`main()`。ここにロジックを書かない。

## リアルタイムの制約

オーディオコールバックの中では、確保も解放もしない、ロックも取らない、例外も投げない、I/O もログも出さない。

守れているかを目視に頼らないよう、リアルタイム側に渡るデータはあらかじめ確保しておき、制御側との受け渡しはロックフリーのキューに限定する。

リアルタイムで走る範囲は `// realtime-begin` と `// realtime-end` で囲む。`test/realtime.sh` がその中を見張る。
