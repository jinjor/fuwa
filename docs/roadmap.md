# ロードマップ

## Step 0: 土台

音が出るところまでの最小構成を作る。あわせて以降の実装が倣うための構造とハーネスを敷く。

言語選定の逃げ道はない。VST3 の ABI は C++ で、SDK も C++、プラグインエディタの埋め込みも ObjC++ が要る。C++ で書けないなら他の言語ではもっと書けないので、ここは検証ではなく単に土台作りとして進める。

- [x] ディレクトリ構成と責務境界の設計、およびそのお手本となる実装
- [x] 開発ハーネスの整備（ASan / UBSan、テスト、ビルド）
- [x] CoreAudio によるオーディオ出力
- [x] VST3 プラグインをロードして、ハードコードしたノートを鳴らす CLI 実行ファイル
- [x] オフラインレンダリングによる自動テスト（音が鳴っていることを耳以外で確かめる）
- [x] hostchecker による規格適合の確認（Error 0、Warning 0）
- [x] 実在のプラグインでの動作確認
- [x] リント（clang-format / clang-tidy）
- [x] 開発環境の再現（./setup.sh）

## MVP: AI がノートを打つと鳴る

AI に「ドレミファソを鳴らして」と頼むとノートが打たれて再生される状態。

- IPC サーバ
- ノート操作 API（トラックと小節範囲をアドレスとして扱えること）
- 再生制御 API
- Skill（AI に API の使い方を教える）

含まないもの: UI、保存、書き出し、複数トラック、ミキサー、テンポ変更。

## その先（優先度未定）

- 複数トラックとインストゥルメント
- WebView UI（トラック一覧・トランスポート・ミキサー）
- エージェントの起動と実行（プロセス管理・ストリーム受信・セッション継続）
- プロンプト入力バー
- 選択した範囲をプロンプトに渡す
- VST3 インストゥルメントの選択 UI とプラグインエディタの表示
- ミキサー（音量・パン）
- プロジェクトの保存形式
- オーディオ書き出し（wav / mp3 / ogg）
- MIDI 入力の添付（その場で弾いたメロディを AI に渡す）
- 音声入力の添付（口ずさんだものを渡す。読み取れるかはモデルの能力次第）
- 添付を読むためのプログラムと Skill（エージェントに毎回書かせるとトークンを使うため）
